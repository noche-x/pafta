# City Terrain Generation — Verified Native Pipeline and Editor Port

Ground truth: `subrosa.exe` (`/subrosa.exe.THIS_ONE` in Ghidra, image base 0),
decompiled 2026-06-12/13. This document supersedes the earlier exploratory docs
(`RE_terrain_full_build.md`, `RE_terrain_cleanroom.md`, `RE_terrain_spec.md`)
where they conflict; every claim here was re-verified against the binary and is
what `src/scene.cpp` implements for the Game Preview.

Editor port: `src/scene.cpp` — `native_like_city_terrain_height`,
`CityCornerStampMap`, `apply_native_city_terrain_patch`, `build_city_terrain`.

## Pipeline overview (World_LoadMapAndInitializeTerrain @56980)

```
1. Terrain_GenerateIslandHeightfield @56560     base island, 2049^2 source grid
2. CitySbc_Load                                  street graph from city2.sbc
3. MapConnector_PlaceStreetSegmentTilesAndSlopes @20580   road tiles + corner stamps
   MapConnector_PlaceIntersectionPerimeterTiles  @20130   footprints + curbs (no stamps)
4. extent expansion: every positive intersection extent += 1
5. district cells (ApplyAllCityDistrictCellsToWorld @20000) + building
   instantiation (InstantiateSbbVolumeIntoWorldAndMetadata @23d00) — both stamp
6. Terrain_RebuildLandTilesRoadPatchesAndChunkCaches @d12e0
   a. bilinear 8x upsample of the source grid into the runtime land tiles
   b. 28 hardcoded intersection block patches (@d3340)
```

The final runtime heightfield is 16384x16384 samples, 1 world unit per sample,
8x8 chunks of 2049^2 floats with shared borders. World-to-sample mapping is
`sample = world + 4096`; stored heights are world Y directly.

## 1. Base island heightfield (@56560)

Source grid: 2049x2049 floats, one sample per 8 world units. For each source
sample `(c, r)` (c = column = X axis, r = row = Z axis), with three value-noise
octaves from `TerrainNoiseHash @1305f0`:

```
r1 = clamp(dist((c,r),(640,640)) / 256 - 0.5, 0, 3); r1sq = r1*r1
n1 = noise(c/64,  r/128)        n2 = noise(c/128, r/128)        n3 = noise(c/64, r/64)
r2 = clamp((dist((c,r),(704,704)) - 320) / 64, 0, 1)
inner  = n3*8 + 23.8125 + (n1 + r1sq)*16 + (n2*32 + r1sq*8)*r1sq
height = inner*r2 + (1 - r2)*23.875
```

Inside the `r2 == 0` core (the whole city) the field is a constant 23.875; the
island only rises far outside. Noise hash (mask = 0xffffffff):

```
u = ((z+1 & m)*0x39 + (x+1 & m));  u ^= u << 13
v = u*u*0x3d73 + 0xc0ae5;  return (v*v + 0xd208dd0d) & 0x7fffffff   // -> [0,2) via 2^-30
```

### Shoreline carving (city maps only, isMapAutoGenerated == 0)

Two literal regions overwrite the island with a water shelf at 11.75, ramped up
by the cubic `(36 - 24e)*e^2 + 11.75` over 4 source samples at the boundary:

```
Region A (rows <= 637, cols < 768):
  e = clamp01(max(1 - min1((638 - r)*0.25), 1 - min1((768 - c)*0.25)))
Region B (cols < 638, rows < 768), applied after A:
  colTerm = (r < 638) ? 0 : 1 - min1((638 - c)*0.25)
  e = clamp01(max(colTerm, 1 - min1((768 - r)*0.25)))
```

In world units this is the NW waterfront: water where `wz < ~1008` (for
`wx < ~2056`) and where `wx < ~1016` (for `wz < ~2048`), right at the city edge
(city spans world ~1024..2592).

## 2. The 8x upsample (@d12e0)

Each source cell is expanded into 8x8 runtime samples by bilinear interpolation
with step 1/8. The corner selection is asymmetric: X interpolates between
`H[r][c-1]` and `H[r][c]` (one-sample shift, guarded by -4096 sentinels stored
just before the array), Z between `H[r][c]` and `H[r+1][c]`. The continuous
equivalent the editor samples is `(gx, gz) = ((wx + 4088)/8, (wz + 4096)/8)`.

## 3. Corner-stamp grid (UpdateMapTopHeightAndClearOccupancyBit @3fa40)

A 4096x4096 float grid indexed by tile-grid corners (NOT terrain samples; one
tile = 4 world units). `stamp(gx, gz, h)` max-updates the four corners of tile
`(gx, gz)`: `(gx,gz) (gx+1,gz) (gx,gz+1) (gx+1,gz+1)`. The older docs'
"four mapTopHeight buffers" are these four corner offsets of one grid.

All stampers:

| Source | What | Height |
|---|---|---|
| street tiles (@20580) | every lane+curb tile column, span `[-leftW-1, rightW]` | current run `level * 4.0` |
| district/piece cells (@20000) | every occupied cell of each 8^3 district volume | cell's own `(districtY*8 + ly) * 4.0` |
| buildings (@23d00) | occupied cells of the ANCHOR layer only | placement record `y * 4.0` |

Intersection footprints do NOT stamp. In the editor, districts are the .sbc
portals (`fields[1..3]` = position in 8-cell units, voxel index `y*64+z*8+x`)
and building footprints come from the placement-resolved .sbb anchor layer run
through the verified city placement transform.

## 4. Intersection block patches (@d3340)

For exactly these 28 hardcoded intersection indices — on ANY non-auto-generated
map, regardless of content:

```
2 40 32 46 45 47 28 10 33 42 35 13 59 31 52 48 50 19 22 58 62 61 41 36 43 44 38 39
```

Skipped unless the intersection has a full block: a south (+x) neighbor with a
west street, a west (+z) neighbor with a south street, and that neighbor's south
neighbor with an east street — each walk may skip ONE intermediate intersection
(so blocks can span two street cells and contain crossing streets).

Patch rect (uses the post-placement +1-expanded extents; the far corners
subtract the same +axis extents as the near corners — native quirk):

```
P0 = (A.gx + A.ext_x_pos)*4    P1 = (B.gx - B.ext_x_pos)*4
Q0 = (A.gz + A.ext_z_pos)*4    Q1 = (C.gz - C.ext_z_pos)*4
corner heights = intersection level*4 + 4.25  (the drivable road surface)
```

Phases:

1. **Bilinear surface** over `[P0..P1] x [Q0..Q1]` between the four corner
   intersection surfaces. Block interiors end up flush with the road tops.
2. **Seeding**: each 4x4-sample tile whose four corner stamps are all > 0 is
   road/plot interior; its 5x5 sample grid is seeded (weight 1.0) and the
   terrain there is rewritten to the bilinear of the four corner-stamp heights.
   Stamps are `level*4.0` — 4.25 below the block surface, so roads cut grooves
   and building plots sink to their bases.
3. **Propagation**: 16 passes; every non-seed sample collects up to two
   candidates from its 8-neighborhood. A candidate carries the ORIGINAL seed
   coordinates; weight = `1 - dist_to_seed/16` (dropped at <= 0). Candidates
   from a parallel direction (dot > 0 against an existing one) replace it only
   if heavier; otherwise new directions append up to the cap of two.
4. **Merge**: per sample, `ratio = w0 / min(w0+w1, 1)`, smoothstep
   `s = (3-2r)r^2` blends the two seeds' terrain heights into a target, then the
   final write is `lerp(current, target, smoothstep(max weight))`.

Net effect: city blocks are bilinear plates between their corner intersections;
roads and stamped plots inside the block pull the terrain down/up to their own
levels with a ~16-sample smoothstep feather; everything outside the 28 rects
stays raw island (flat 23.875 in the core).

## 5. Vertical conventions

- World cells at level `L` span `[L*4 + 0.25, L*4 + 4.25]` (the +0.25 area
  offset). Road tops, the patch corner heights, and building ground floors all
  land on `L*4 + 4.25`.
- Curb plates are the bottom 1/16 (0.25 world units) of the `L+1` cell:
  `[L*4 + 4.25, L*4 + 4.5]`, flush with patched block ground, a 0.25 lip above
  the road.
- Native intersection records store `level = sbc_y - 1` (the loader subtracts
  one); buildings/districts use their record values directly.
- The editor lifts pieces and city buildings by the same +0.25 so their bottoms
  sit above the stamped terrain plots instead of z-fighting them.

## 6. Terrain removal (the land-use mask)

`landscape.frag` discards a fragment when its bit in the land-use mask
(`g_landUseMaskBits`, one bit per 4-unit world cell, 4x4 cells per u16 texel)
is clear. The mask starts all ones; `UpdateMapTopHeightAndClearOccupancyBit`
clears the bit of every cell it stamps that lies inside the intersections'
bounding box (`0x35fd1444..0x35fd1458`). So the landscape is cut away under
street tiles, district cells, and building anchor-layer footprints, and nowhere
else; intersection footprints keep their terrain. On `isMapAutoGenerated` maps
(`round`) the stamp function returns at once: no mask, no stamps, no patches,
no shoreline cut. The editor records the cleared cells in
`CityCornerStampMap::masked` and skips terrain quads whose four corners lie in
masked cells. The `terrain.heights` query grid is left intact.

Later world writes replace street cells: district cells overwrite their cell,
and `InstantiateSbbVolumeIntoWorldAndMetadata @23ac0` deletes the block in every
cell of the building volume that has an exterior block word before writing its
own. The editor drops road/curb tiles in those cells
(`remove_replaced_city_tiles`).

## 7. Editor port deltas (deliberate)

- Heightfield computed at the native 1-unit resolution over the city bounds
  +24-tile padding only; the render mesh samples it every 2 units, offset
  -0.05 to keep coplanar road tops on top.
- Sloped road cells render as continuous tilted tops; the game pre-bakes
  discrete 1/16-step tilted block meshes (Buildblock_InitTemplateMeshCatalog
  @10110). Visually equivalent (verified earlier).
- Patch propagation runs on a rect-sized scratch grid instead of the game's
  fixed 256-wide static buffer; identical math, no 256-sample wrap bug.
- Shading is an editor-side bake (directional + ambient with exaggerated
  horizontal normals); the game uses PBR + shadow maps. NOTE: the terrain and
  tile top faces wind so their geometric normal points DOWN (`e1xe2 = -Y`); the
  bake flips any downward normal up before lighting, otherwise every ground face
  clamps to the ambient floor and slopes read flat.
- Traffic-light poles: the model arm points local -Z; raylib's +Y yaw is
  right-handed, so the draw yaw is `atan2(-arm.x, -arm.z)` (the X component is
  negated, same handedness flip as the building rotations).
