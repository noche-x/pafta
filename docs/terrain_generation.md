# City terrain generation and the Pafta port

The findings about the game come from `subrosa.exe` (`/subrosa.exe.THIS_ONE` in Ghidra, image base 0), studied on 2026-06-12 and 2026-06-13. Where they disagree with the earlier notes (`RE_terrain_full_build.md`, `RE_terrain_cleanroom.md`, `RE_terrain_spec.md`), this page is right. The code references point at the terrain functions in `src/scene.cpp`. Whether the result looks like the game needs its own side-by-side check.

Pafta code: `src/scene.cpp`: `native_like_city_terrain_height`, `CityCornerStampMap`, `apply_native_city_terrain_patch`, `build_city_terrain`.

## The steps (World_LoadMapAndInitializeTerrain @56980)

```
1. Terrain_GenerateIslandHeightfield @56560     base island, 2049^2 source grid
2. CitySbc_Load                                  street graph from city2.sbc
3. MapConnector_PlaceStreetSegmentTilesAndSlopes @20580   road tiles + corner stamps
   MapConnector_PlaceIntersectionPerimeterTiles  @20130   footprints + curbs (no stamps)
4. extent expansion: every positive intersection extent += 1
5. district cells (ApplyAllCityDistrictCellsToWorld @20000) + building
   instantiation (InstantiateSbbVolumeIntoWorldAndMetadata @23d00), both stamp
6. Terrain_RebuildLandTilesRoadPatchesAndChunkCaches @d12e0
   a. bilinear 8x upsample of the source grid into the runtime land tiles
   b. 28 hardcoded intersection block patches (@d3340)
```

The final heightfield is 16384x16384 samples, one per world unit, split into 8x8 chunks of 2049^2 floats that share their edges. To go from world to sample, use `sample = world + 4096`. Heights are stored as world Y.

## 1. The base island (@56560)

The source grid is 2049x2049 floats, one sample every 8 world units. For each sample `(c, r)` (c is the column on the X axis, r is the row on the Z axis), the game mixes three layers of value noise from `TerrainNoiseHash @1305f0`:

```
r1 = clamp(dist((c,r),(640,640)) / 256 - 0.5, 0, 3); r1sq = r1*r1
n1 = noise(c/64,  r/128)        n2 = noise(c/128, r/128)        n3 = noise(c/64, r/64)
r2 = clamp((dist((c,r),(704,704)) - 320) / 64, 0, 1)
inner  = n3*8 + 23.8125 + (n1 + r1sq)*16 + (n2*32 + r1sq*8)*r1sq
height = inner*r2 + (1 - r2)*23.875
```

Inside the area where `r2 == 0` (the whole city), the height is a flat 23.875. The island only rises far outside it. The noise hash (mask = 0xffffffff):

```
u = ((z+1 & m)*0x39 + (x+1 & m));  u ^= u << 13
v = u*u*0x3d73 + 0xc0ae5;  return (v*v + 0xd208dd0d) & 0x7fffffff   // -> [0,2) via 2^-30
```

### Cutting the shoreline (city maps only, isMapAutoGenerated == 0)

Two fixed regions replace the island with a shallow water shelf at 11.75. At the edge, the height ramps up over 4 source samples along the curve `(36 - 24e)*e^2 + 11.75`:

```
Region A (rows <= 637, cols < 768):
  e = clamp01(max(1 - min1((638 - r)*0.25), 1 - min1((768 - c)*0.25)))
Region B (cols < 638, rows < 768), applied after A:
  colTerm = (r < 638) ? 0 : 1 - min1((638 - c)*0.25)
  e = clamp01(max(colTerm, 1 - min1((768 - r)*0.25)))
```

In world units, this is the waterfront on the north-west side. There is water where `wz < ~1008` (for `wx < ~2056`) and where `wx < ~1016` (for `wz < ~2048`), right at the edge of the city, which runs from about 1024 to 2592.

## 2. Scaling up 8x (@d12e0)

Each source cell becomes 8x8 runtime samples, filled in with bilinear interpolation in steps of 1/8. The corners are picked unevenly. X blends between `H[r][c-1]` and `H[r][c]` (shifted by one sample, with -4096 guard values stored just before the array). Z blends between `H[r][c]` and `H[r+1][c]`. In continuous terms, Pafta samples at `(gx, gz) = ((wx + 4088)/8, (wz + 4096)/8)`.

## 3. The corner-stamp grid (UpdateMapTopHeightAndClearOccupancyBit @3fa40)

This is a 4096x4096 float grid indexed by the corners of tiles, not by terrain samples. One tile is 4 world units. `stamp(gx, gz, h)` raises the four corners of tile `(gx, gz)` to at least `h`: `(gx,gz) (gx+1,gz) (gx,gz+1) (gx+1,gz+1)`. The "four mapTopHeight buffers" in the older notes are just these four corner offsets into one grid.

Everything that stamps:

| Source | What | Height |
|---|---|---|
| street tiles (@20580) | every lane and curb tile column, span `[-leftW-1, rightW]` | current run `level * 4.0` |
| district/piece cells (@20000) | every filled cell of each 8^3 district volume | the cell's own `(districtY*8 + ly) * 4.0` |
| buildings (@23d00) | filled cells of the ANCHOR layer only | placement record `y * 4.0` |

Intersection footprints do not stamp. In Pafta, districts are the .sbc portals (`fields[1..3]` give the position in 8-cell units, and the voxel index is `y*64+z*8+x`). Building footprints come from the .sbb anchor layer, moved into place with the checked city placement transform.

## 4. Intersection block patches (@d3340)

This runs for exactly these 28 hardcoded intersection numbers, on any map that is not auto-generated, whatever the map contains:

```
2 40 32 46 45 47 28 10 33 42 35 13 59 31 52 48 50 19 22 58 62 61 41 36 43 44 38 39
```

An intersection is skipped unless it closes a full block. That means a south (+x) neighbour with a west street, a west (+z) neighbour with a south street, and that neighbour's south neighbour with an east street. Each of these steps may jump over ONE intersection in between, so a block can cover two street cells and have streets crossing it.

The patch rectangle uses the extents after the +1 growth in step 4. The far corners subtract the same +axis extents as the near corners do; this is a quirk of the game:

```
P0 = (A.gx + A.ext_x_pos)*4    P1 = (B.gx - B.ext_x_pos)*4
Q0 = (A.gz + A.ext_z_pos)*4    Q1 = (C.gz - C.ext_z_pos)*4
corner heights = intersection level*4 + 4.25  (the drivable road surface)
```

The patch happens in four phases:

1. Bilinear surface over `[P0..P1] x [Q0..Q1]`, between the road surfaces of the four corner intersections. The inside of the block ends up level with the tops of the roads.
2. Seeding. Each 4x4-sample tile whose four corner stamps are all > 0 counts as road or plot. Its 5x5 sample grid gets seeded (weight 1.0), and the terrain there is rewritten to the bilinear blend of the four corner-stamp heights. Stamps are `level*4.0`, which is 4.25 below the block surface, so roads cut grooves and building plots sink down to their bases.
3. Spreading. 16 passes. Every sample that is not a seed picks up to two candidates from its 8 neighbours. A candidate keeps the ORIGINAL seed's coordinates, with weight `1 - dist_to_seed/16` (dropped at <= 0). A candidate from a parallel direction (dot > 0 with one already held) only replaces it if it is heavier. Otherwise new directions are added, up to two.
4. Merging. For each sample, `ratio = w0 / min(w0+w1, 1)`, and the smoothstep `s = (3-2r)r^2` blends the two seeds' terrain heights into a target. The final value is `lerp(current, target, smoothstep(max weight))`.

The result: city blocks are flat-ish bilinear plates between their corner intersections. Roads and stamped plots inside a block pull the terrain down or up to their own level, with a soft edge about 16 samples wide. Everything outside the 28 rectangles stays as the raw island (a flat 23.875 in the middle).

## 5. Heights

- World cells at level `L` cover `[L*4 + 0.25, L*4 + 4.25]` (the +0.25 area offset). Road tops, the patch corner heights, and building ground floors all sit at `L*4 + 4.25`.
- Curb plates are the bottom 1/16 (0.25 world units) of cell `L+1`: `[L*4 + 4.25, L*4 + 4.5]`. That makes them level with the patched block ground, and 0.25 above the road.
- The game stores intersection levels as `level = sbc_y - 1` (the loader subtracts one). Buildings and districts use their record values as they are.
- Pafta raises pieces and city buildings by the same +0.25, so their bottoms sit above the stamped plots instead of flickering against them.

## 6. Removing terrain (the land-use mask)

`landscape.frag` throws away a pixel when its bit in the land-use mask is clear (`g_landUseMaskBits`, one bit per 4-unit world cell, 4x4 cells per u16 texel). The mask starts as all ones. `UpdateMapTopHeightAndClearOccupancyBit` clears the bit of every cell it stamps that is inside the bounding box of the intersections (`0x35fd1444..0x35fd1458`). So the ground is cut away under street tiles, district cells, and the anchor-layer footprints of buildings, and nowhere else. Intersection footprints keep their ground. On `isMapAutoGenerated` maps (`round`) the stamp function returns straight away: no mask, no stamps, no patches, and no shoreline cut. Pafta records the cleared cells in `CityCornerStampMap::masked` and skips terrain quads whose four corners are all in cleared cells. The `terrain.heights` grid used for height lookups is left alone.

Later writes into the world replace street cells. District cells overwrite their own cell, and `InstantiateSbbVolumeIntoWorldAndMetadata @23ac0` deletes the block in every cell of the building's volume that has an exterior block word, before writing its own. Pafta drops road and curb tiles in those cells (`remove_replaced_city_tiles`).

## 7. Where Pafta differs on purpose

- Pafta works out the heightfield at the game's 1-unit resolution, but only over the city plus 24 tiles of padding. The render mesh samples it every 2 units, shifted down by 0.05 so road tops at the same height stay on top.
- Sloped road cells are drawn as smooth tilted tops. The game builds tilted block meshes ahead of time in steps of 1/16 (Buildblock_InitTemplateMeshCatalog @10110). An earlier note said these looked the same, but there is no screenshot comparison on record.
- Patch spreading runs on a scratch grid the size of the rectangle instead of the game's fixed 256-wide buffer. The math is the same, without the bug where it wraps at 256 samples.
- The earlier port baked lighting in the editor (sun plus ambient, with the sideways part of the normals exaggerated). Later shader work is described in [RE_render_shader_spec.md](RE_render_shader_spec.md). Terrain and tile tops are wound so their normal points DOWN (`e1xe2 = -Y`). The bake flips any downward normal to point up before lighting; without that, every ground face drops to the ambient minimum and slopes look flat.
- Traffic-light poles: the model's arm points along local -Z. raylib's +Y turn is right-handed, so the draw angle is `atan2(-arm.x, -arm.z)`. The X part is negated, the same handedness flip used for building rotations.
